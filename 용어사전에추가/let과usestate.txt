React에서 let 변수 값 변경과 useState의 가장 큰 차이는 리렌더링(화면 새로고침) 유발 여부와 값의 유지(기억) 여부입니다 [6.2, 6.4, 6.7]. let은 값이 바뀌어도 화면이 바뀌지 않고 초기화되지만, useState는 값이 바뀌면 화면을 다시 그립니다 [6.4, 6.7].
------------------------------
## let 변수의 특징

* 화면 반영 없음: 값을 바꿔도 React가 모릅니다. 화면(UI)이 다시 그려지지 않습니다 [6.4, 6.7].
* 값 초기화: 사용자가 버튼을 누르거나 다른 이유로 컴포넌트가 다시 그려지면, let 변수는 처음 지정했던 초기값으로 다시 돌아갑니다 [6.4].
* 용도: 화면과 상관없는 임시 계산이나 데이터 저장에 씁니다 [6.7].

## useState의 특징

* 화면 자동 업데이트(리렌더링): 상태 변경 함수(setState)를 쓰면 값이 바뀔 때 React가 감지하고 화면을 새롭게 바꿉니다 [6.4, 6.7].
* 값 유지: 컴포넌트가 다시 그려져도 이전 상태 값을 잃지 않고 기억합니다 [6.4, 6.6].
* 용도: 사용자의 입력, 클릭, 서버에서 가져온 데이터 등 화면에 바로 보여야 하는 모든 곳에 씁니다 [6.7, 6.8].

------------------------------
## 비교 요약

| 구분 | let 변수 | useState |
|---|---|---|
| 값 변경 방법 | let x = 1; x = 2; (직접 대입) [6.7, 6.10] | const [x, setX] = useState(1); setX(2); (함수 사용) [6.4, 6.7] |
| 리렌더링(화면 갱신) | 안 됨 [6.4, 6.7] | 됨 [6.4, 6.7] |
| 렌더링 간 값 유지 | 안 됨 (초기화됨) [6.4] | 됨 (기억함) [6.4, 6.6] |
| 주요 사용 목적 | 렌더링과 무관한 내부 로직 [6.7] | 화면(UI)에 반영할 데이터 관리 [6.7] |
