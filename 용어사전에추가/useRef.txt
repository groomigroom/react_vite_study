React (TSX)에서 useRef는 값이 변경되어도 컴포넌트를 리렌더링하지 않고 유지하는 "저장 공간"이자, 
실제 DOM 요소에 직접 접근하기 위한 도구입니다.
------------------------------
## 핵심 특징 2가지

* 
* 리렌더링 방지: useState와 달리 값이 바뀌어도 화면이 다시 그려지지 않습니다. 컴포넌트가 리렌더링되어도 내부 데이터는 초기화되지 않고 유지됩니다. [1, 3] 
* DOM 접근: input 창 포커스, 스크롤 위치 조작, 미디어 재생 등 실제 HTML 엘리먼트를 직접 제어할 때 사용합니다. [2, 3, 4]

## TSX(TypeScript)에서 사용하는 2가지 방법
TypeScript에서는 용도에 따라 제네릭(Generic) 타입과 초기값 설정이 달라집니다. [5] 
## 1. DOM 요소를 참조할 때 (가장 흔한 케이스)
제네릭에 참조할 HTML 태그의 타입을 넣고, 초기값으로 null을 주어야 합니다.
컴포넌트가 처음 그려지기 전(Mount 전)에는 DOM 변수가 비어있기 때문입니다. [5, 6] 

import { useRef, useEffect } from 'react';
function TextInputWithFocusButton() {
  // 1. HTMLInputElement 타입을 지정하고 null로 초기화
  const inputRef = useRef<HTMLInputElement>(null);

  const onButtonClick = () => {
    // 2. TypeScript는 null일 가능성이 있다고 경고하므로 옵셔널 체이닝(?.) 사용
    inputRef.current?.focus();
  };

  return (
    <>
      <input ref={inputRef} type="text" />
      <button onClick={onButtonClick}>인풋창에 포커스</button>
    </>
  );
}

## 2. 리렌더링 없이 값만 저장할 때 (변수 대용)
제네릭에 저장할 데이터의 타입을 넣고, 초기값으로 기본값을 설정합니다.
.current 값을 직접 수정할 수 있는 MutableRefObject 형태로 동작합니다. [5, 7] 

import { useRef } from 'react';
function Timer() {
  // 리렌더링을 유발하지 않는 변수 저장 (예: 타이머 ID)
  const intervalRef = useRef<number>(0);

  const startTimer = () => {
    intervalRef.current = window.setInterval(() => {
      console.log('틱톡');
    }, 1000);
  };

  const stopTimer = () => {
    clearInterval(intervalRef.current);
  };

  return (
    <div>
      <button onClick={startTimer}>시작</button>
      <button onClick={stopTimer}>정지</button>
    </div>
  );
}

React에서 일반 변수(let, const)나 useState 대신 useRef를 꼭 사용해야 하는 이유는 성능 최적화(불필요한 리렌더링 방지)와 컴포넌트 생명주기 동안의 데이터 보존 때문입니다.
쉽게 말해, "화면을 다시 그릴 필요는 없지만, 컴포넌트가 사라지기 전까지 기억해야 하는 값"이 있을 때 사용합니다.
------------------------------
## 1. 화면은 그대로 두고, 값만 몰래 변경하고 싶을 때 (성능 최적화)
useState로 만든 상태(State)가 바뀌면 React 컴포넌트는 무조건 화면을 다시 그립니다(리렌더링). 하지만 화면에 보이지 않는 값을 바꿀 때마다 화면을 다시 그리는 것은 심각한 성능 낭비입니다.

* 배경: 사용자의 스크롤 위치, 모달 창이 열린 횟수, API 요청 중복 방지 플래그 등은 화면에 숫자로 띄우지 않는 이상 리렌더링이 필요 없습니다.
* 해결: useRef를 쓰면 값이 아무리 바뀌어도 화면이 깜빡이지 않아 애플리케이션이 가볍고 빠르게 작동합니다.

## 2. 일반 변수와 달리, 컴포넌트가 리렌더링되어도 값을 유지하고 싶을 때
"그럼 그냥 함수 안에 let count = 0; 같은 일반 변수를 쓰면 안 되나요?"라는 의문이 생길 수 있습니다. 안 되는 이유는 일반 변수는 리렌더링될 때마다 초기화되기 때문입니다.

* 일반 변수: 부모 컴포넌트가 바뀌거나 다른 상태 때문에 컴포넌트가 다시 그려지면, 함수가 처음부터 다시 실행되면서 내부 변수도 초기값으로 리셋됩니다.
* useRef: 컴포넌트가 아무리 많이 다시 그려져도, .current에 저장된 값은 컴포넌트가 완전히 사라질(Unmount) 때까지 안전하게 유지됩니다.

## 3. 실제 HTML 엘리먼트(DOM)를 직접 조작해야 할 때
React는 기본적으로 개발자가 DOM을 직접 만지지 않고 데이터(State)만 바꾸면 화면이 알아서 바뀌도록 설계되어 있습니다. 하지만 현실적으로 DOM을 직접 제어해야만 하는 순간이 있습니다.

* 인풋창 포커스: 로그인 버튼을 누르면 아이디 입력창에 커서가 자동으로 가게 할 때
* 스크롤 제어: 채팅방에 새 메시지가 오면 스크롤을 맨 아래로 강제 이동시킬 때
* 미디어 재생: <video>나 <audio> 태그의 play(), pause() 메서드를 실행할 때
* 크기 측정: 특정 상자(div)의 실제 가로/세로 픽셀 길이를 알아내야 할 때

이때 useRef를 HTML 태그의 ref 속성에 연결하면, JavaScript의 document.getElementById()처럼 해당 태그를 직접 쥐고 흔들 수 있게 됩니다.

## 한눈에 보는 요약 퀴즈

* Q. 화면에 실시간으로 숫자가 올라가는 타이머를 보여줘야 한다면?
* 👉 useState (화면이 바뀌어야 하므로)
* Q. 타이머를 멈추기 위해 setInterval ID를 보관해야 한다면?
* 👉 useRef (ID는 화면에 안 보이고, 리렌더링돼도 유지되어야 하므로)
* Q. 컴포넌트 안에서 임시로 숫자 1과 2를 더한 값을 구하고 끝낼 거라면?
* 👉 일반 변수 const sum = 1 + 2;

현재 작성 중이신 코드에서 어떤 값을 저장하거나 어떤 DOM을 제어하려고 하시나요? 하시는 작업의 목적을 공유해주시면 useRef가 정답이 맞는지, 혹은 더 나은 대안이 있는지 봐 드릴게요.
