useRef

React TSX(TypeScript)에서 useRef는 리렌더링을 유발하지 않고 값을 유지하거나 특정 DOM 요소에 직접 접근할 때 사용하는 훅입니다. 
TSX 환경에서는 안전한 타입 지정을 위해 제네릭을 활용합니다.
주요 의미와 용도
DOM 직접 제어: 입력창 포커스, 스크롤 위치 이동 등 HTML 요소에 직접 접근.
값 저장: 타이머 ID, 이전 값 등 화면 표출(렌더링)과 관계없는 데이터를 보존.
리렌더링 방지: current 값이 바뀌어도 컴포넌트가 다시 그려지지 않아 성능 최적화에 기여.
TypeScript(TSX)에서의 특징
타입 추론과 제네릭: useRef<HTMLInputElement>(null)처럼 초기값과 DOM 타입을 명시해야 안전합니다.
Readonly vs Mutable: 초기값 유무에 따라 읽기 전용(RefObject) 또는 수정 가능(MutableRefObject) 타입으로 다르게 지정됩니다.

리렌더링

웹사이트(특히 리액트 같은 프론트엔드 프레임워크)에서 리렌더링이 유발되는 주요 이유는 상태(State) 변경,
속성(Props) 변경, 그리고 부모 컴포넌트의 리렌더링 때문이다.
주요 리렌더링 유발 원인상태(State) 변화: useState 등으로 관리되는 값이 set 함수를 통해 바뀔 때
속성(Props) 변화: 부모가 넘겨준 전달값이 새로 업데이트될 때
부모의 리렌더링: 부모 컴포넌트가 다시 실행되면 하위에 있는 자식 컴포넌트들도 기본적으로 함께 다시 호출됨
컨텍스트(Context) 변화: useContext로 구독 중인 전역 데이터가 바뀔 때

const timeoutRef = useRef<ReturnType<typeof setTimeout> | null>(null); 
코드는 브라우저 또는 Node.js 환경에서 setTimeout 함수의 타이머 ID를 안전하게 저장하고 관리하기 위한 타입스크립트의 참조(useRef) 선언입니다.
구성 요소별 의미는 다음과 같습니다:
useRef<T>(null) 리렌더링을 유발하지 않는 가변(mutable) 값을 저장하는 객체를 만듭니다. 

가변(mutable) 값
리액트(React)와 JSX에서 가변(mutable) 값은 생성된 이후 내부의 데이터나 상태를 직접 수정(mutation)할 수 있는 객체나 배열 같은 참조 타입 데이터를 의미합니다. 
리액트에서는 상태(State)를 가변 값처럼 직접 수정하면 화면이 다시 그려지지 않거나 오류가 생기므로, 
값을 바꿀 때 불변성(Immutability)을 지켜 새 껍데기로 교체해야 합니다.
가변 값의 핵심 특징
직접 수정 가능: 메모리에 있는 원래 데이터의 속성이나 요소를 직접 바꿀 수 있습니다.
참조 주소 유지: 데이터의 내용은 바뀌어도 변수가 가리키는 메모리 주소는 그대로 유지됩니다.
리액트 상태 제약: useState로 만든 상태를 직접 고치면 리액트가 변경을 알아차리지 못합니다.
리액트에서의 주의점
직접 변경 금지: state.push()나 state.value = 1처럼 직접 값을 바꾸는 가변 방식은 피해야 합니다.
세터 함수 사용: 대신 setState를 통해 새로운 객체나 배열을 전달하여 값을 갱신해야 안전합니다.
예외(Ref): useRef는 값이 변해도 화면을 다시 그리지 않는 가변 값을 관리할 때 예외적으로 사용합니다.

useRef<T>(null)이 가변값(RefObject 또는 MutableRefObject)으로 다뤄지는 이유는 초기 생성 시점의 DOM 미지정 상태, 
값의 변경 가능성, 그리고 생명주기 동안 .current 값이 교체되기 때문입니다.
핵심 이유
DOM 부재: 컴포넌트 실행 초기에는 실제 DOM 노드가 생성되지 않아 null이며, 
렌더링 후 요소가 마운트될 때 값이 할당됩니다.
읽기 전용 vs 수정 가능: null을 전달하면 타입스크립트는 .current를 바꿀 수 없는 읽기 전용(RefObject)으로 처리하여 DOM 레퍼런스가 함부로 손상되지 않도록 보호합니다.
생명주기 연동: 컴포넌트가 언마운트되면 null로 다시 재설정되는 동적 특성을 갖습니다.

초기값은 null로 설정합니다.
typeof setTimeout: 전역 함수인 setTimeout 자체의 타입(시그니처)을 가리킵니다.
ReturnType<...>: 특정 함수가 반환하는 결과값의 타입을 자동으로 추출해 주는 타입스크립트 유틸리티 타입입니다. 
즉, setTimeout이 반환하는 ID의 타입(number 혹은 NodeJS.Timeout)을 환경에 맞게 정확히 가져옵니다.
| null: 타이머가 아직 작동하지 않았거나 비워진 상태를 나타내기 위해 타입에 null을 허용합니다.
주요 활용 목적
크로스 플랫폼 호환성: 웹 브라우저(window.setTimeout은 숫자 반환)와 Node.js(NodeJS.Timeout 객체 반환) 환경 차이로 인한 타이머 ID 타입 에러를 방지합니다.
타이머 제어: clearTimeout(timeoutRef.current) 등을 통해 이전에 실행된 타이머를 안전하게 취소하고 메모리 누수를 막을 때 사용합니다.

## 1. useEffect(() => { ... }, [currentIndex]);

* 의미: currentIndex 값이 변경될 때마다 이 useEffect 블록 내부의 코드를 새로 실행합니다.
* 작동: 맨 처음 컴포넌트가 나타날 때(Mount) 실행되고, 
이후 3초마다 currentIndex가 바뀔 때마다 기존 타이머를 깨끗이 지우고 새로운 3초 타이머를 다시 시작합니다.

React의 useEffect에서 마지막에 있는 [currentIndex]는 **의존성 배열(Dependency Array)**이라고 부릅니다.
이 배열의 의미와 역할은 다음과 같습니다.
핵심 역할
재실행 조건: currentIndex 값이 변경될 때마다 useEffect 내부의 코드가 다시 실행됩니다.
타이머 갱신: 인덱스가 바뀌면 기존 타이머를 취소하고, 
3초 뒤 다음 인덱스로 넘어가도록 새로운 타이머를 작동시킵니다.
동작 과정
최초 실행: 컴포넌트가 처음 화면에 나타날 때 타이머가 시작됩니다.
3초 후: setCurrentIndex가 호출되어 currentIndex 값이 바뀝니다.
정리(Cleanup): currentIndex가 바뀌었으므로, return 함수가 실행되어 기존 타이머를 없앱니다 
(clearTimeout).재실행: 새로운 currentIndex 값을 가지고 useEffect 내부 코드가 다시 실행되어 새로운 3초 타이머가 시작됩니다.
만약 배열을 다르게 바꾼다면?[] (빈 배열): 컴포넌트가 처음 켜질 때 딱 한 번만 실행됩니다.
3초 뒤에 인덱스가 1등으로 한 번만 바뀌고, 그 이후에는 타이머가 다시 작동하지 않아 숫자가 멈춥니다.
배열 생략 ([currentIndex] 자체를 삭제): 컴포넌트가 리렌더링될 때마다 타이머가 계속 새로 만들어져서 화면이 무한히 빠르게 바뀔 수 있습니다.

리액트(TSX)에서 의존성 배열(Dependency Array)은 특정 값의 변경 감지, [훅(Hook)의 실행 시점 제어](0.6.2, 0.6.10), 불필요한 연산 방지 역할을 하는 두 번째 인수입니다.의존성 배열의 형태별 의미배열을 아예 쓰지 않음: 컴포넌트가 다시 그려질(렌더링) 때마다 매번 실행됩니다.빈 배열 []만 넣음: 컴포넌트가 처음 화면에 나타날 때(마운트) 딱 한 번만 실행됩니다.값이 들어있는 배열 [prop, state]: 배열 안의 값이 바뀔 때만 실행됩니다.

## 2. timeoutRef.current = setTimeout(() => { ... }, 3000);

* setTimeout(..., 3000): 3초(3000ms) 후에 중괄호 {} 안의 화살표 함수를 실행하라는 명령입니다.
* timeoutRef.current = ...: 브라우저가 발급해 준 이 타이머의 고유 ID 번호를 timeoutRef에 보관합니다. 
컴포넌트가 리렌더링되어도 이 ID 번호는 지워지지 않고 안전하게 유지됩니다.

## 3. setCurrentIndex((prev) => prev + 1);

* 의미: 3초가 지나면 현재 인덱스 값(prev)에 1을 더해서 상태를 업데이트합니다.
* 결과: 이 상태 업데이트로 인해 컴포넌트가 다시 렌더링되고, 
의존성 배열에 있는 currentIndex가 변경되었으므로 useEffect가 다시 처음부터 발동합니다. 
(이 과정이 무한 반복됩니다.)

## 4. return () => { ... }; (클린업 함수)

* 의미: React에서 useEffect가 새로 실행되기 직전, 
또는 컴포넌트가 화면에서 사라질 때(Unmount) 기존에 켜두었던 타이머를 끄는 청소 부품입니다.
* 왜 필요한가?: 만약 이 청소 코드가 없다면, 유저가 페이지를 이동하거나 값이 바뀔 때마다 유령 타이머들이 메모리에 계속 쌓여서 앱이 느려지거나 에러가 발생합니다.

## 5. if (timeoutRef.current) clearTimeout(timeoutRef.current);

* 의미: "만약 timeoutRef.current에 저장된 타이머 ID가 존재한다면, 그 타이머 작동을 취소(clearTimeout)하겠다"는 뜻입니다.
* 작동: 안전하게 기존 타이머를 파괴하여 메모리 누수(Memory Leak)를 방지합니다.

## 전체적인 실행 흐름 요약 (타임라인)

   1. [0초] 컴포넌트 등장 ➡️ useEffect 실행 ➡️ 1번 타이머(3초 뒤 실행) 등록 및 ID 저장.
   2. [3초] 3초 경과 ➡️ 1번 타이머 발동 ➡️ setCurrentIndex로 값 변경.
   3. [리렌더링] 값이 바뀌어 컴포넌트가 다시 그려짐 ➡️ useEffect 재실행 타이밍.
   4. [청소] 새 타이머를 틀기 전, 클린업 함수가 실행되어 방금 끝난 1번 타이머를 완전 제거.
   5. [반복] 곧바로 2번 타이머(다시 3초 뒤 실행) 등록 ➡️ 3초 후 또 실행.

제공해주신 코드는 애니메이션이나 슬라이더, 팝업 등에서 트랜지션(화면 전환 효과)이 부드럽고 자연스럽게 시작되도록 0.05초(50ms)의 미세한 지연 시간(Delay)을 주는 코드입니다.
브라우저가 HTML 요소를 화면에 먼저 그리고(Rendering), 아주 잠깐의 시간차를 둔 뒤 클래스나 스타일을 바꾸어 CSS 애니메이션을 발동시킬 때 주로 사용하는 패턴입니다.

## 1. useEffect(() => { ... }, [isTransitioning]);

* 의미: 전환 상태를 나타내는 isTransitioning 값이 변경될 때마다 이 useEffect 내부의 코드를 실행합니다.
* 작동: 최초 렌더링 시 실행되고, 이후 isTransitioning 값이 true나 false로 바뀔 때마다 다시 실행됩니다.

## 2. if (!isTransitioning) { ... }

* 의미: "만약 현재 트랜지션(전환)이 진행 중이 아니라면 (false 상태라면)" 내부 코드를 실행하라는 조건문입니다.
* 목적: 이미 isTransitioning이 true인 상태(전환 중인 상태)일 때는 중복해서 타이머를 켜지 않도록 방어막을 쳐둔 것입니다.

## 3. const timer = setTimeout(() => { ... }, 50);

* 50: 0.05초(50ms)를 의미합니다. 사람이 느끼기엔 눈 깜짝할 새 부드럽게 이어지는 찰나의 시간입니다.
* 의미: 브라우저가 현재 화면을 안정적으로 그린 직후, 0.05초 뒤에 중괄호 {} 안의 명령을 실행하도록 예약합니다.
* 특징: 이전 질문과 다르게 useRef를 쓰지 않고 const timer라는 일반 로컬 변수에 타이머 ID를 담았습니다. 이는 이 타이머가 오직 이 useEffect 블록 내부에서만 잠깐 쓰이고 사라질 용도이기 때문입니다.

## 4. setIsTransitioning(true);

* 의미: 0.05초가 지나면 트랜지션 상태를 true로 바꿉니다.
* 결과: 이 상태가 true가 되면 컴포넌트가 리렌더링되면서 특정 HTML 요소에 CSS 클래스(예: .active, .fade-in)가 붙거나 스타일이 바뀌며 부드러운 애니메이션이 시작됩니다.

## 5. return () => clearTimeout(timer); (클린업 함수)

* 의미: 0.05초가 지나기 전에 컴포넌트가 화면에서 갑자기 사라지거나(Unmount), isTransitioning 값이 바뀌면 방금 켜둔 0.05초짜리 타이머를 취소합니다.
* 목적: 찰나의 순간이라도 메모리 누수나 엇박자 에러가 나지 않도록 안전장치를 걸어둔 것입니다.

------------------------------
## 이 코드가 꼭 필요한 이유 (개발자 팁)
리액트에서 상태를 바꿈과 동시에 CSS 애니메이션을 주려고 하면, 브라우저가 화면을 그리는 속도와 리액트의 상태 변경 속도가 꼬여서 애니메이션이 뚝 끊기거나 아예 작동하지 않는 현상이 발생하곤 합니다.
이 코드처럼 50ms 정도의 아주 미세한 틈을 주면, 브라우저가 준비를 마친 상태에서 isTransitioning = true가 되므로 CSS Transition 효과가 아주 부드럽고 정확하게 발동하게 됩니다.
------------------------------
혹시 이 코드는 이미지 슬라이더가 끝에서 처음으로 되돌아갈 때 딱딱하게 끊기는 현상을 막기 위한 눈속임용 코드인가요? 아니면 모달/팝업창이 부드럽게 서서히 나타나도록(Fade-in) 구현하는 중이신가요? 어떤 기능에 이 코드를 접목하고 계시는지 말씀해 주시면 CSS 결합 방법이나 추가 팁을 드릴 수 있습니다.

제공해주신 코드는 무한 루프(Infinite Loop)가 가능한 완성도 높은 이미지 슬라이더(캐러셀)의 View(렌더링) 부분입니다.
이 코드의 핵심은 마지막 슬라이드에서 다음으로 넘어갈 때, 혹은 첫 슬라이드에서 이전으로 갈 때 눈속임을 주기 위해 SLIDES 배열(앞뒤로 가짜 슬라이드가 붙은 배열)과 IMAGES 배열(실제 이미지 원본 배열)을 분리해서 다루고 있다는 점입니다.
구조별로 한 줄씩 자세히 해석해 드립니다.

## 1. 최상위 부모 컨테이너 (<div style={{ ... }}>)

position: "relative",      // 내부 인디케이터(점)를 절대 위치(absolute)로 잡기 위한 기준점
width: "100%",             // 반응형 너비
maxWidth: "600px",         // 가로 최대 크기 제한
margin: "50px auto",       // 화면 중앙 정렬
overflow: "hidden",        // 💡 중요: 옆으로 나열된 다른 슬라이드들이 화면 밖에 안 보이게 숨김
borderRadius: "8px",       // 테두리 둥글게
boxShadow: "...",          // 은은한 그림자 효과

## 2. 슬라이드 컨테이너 (<div onTransitionEnd={...} style={{ ... }}>)
가장 중요한 핵심 움직임을 담당하는 박스입니다. 슬라이드들이 가로로 길게 배치되어 있고, 이 박스 전체가 통째로 왼쪽/오른쪽으로 움직입니다.

onTransitionEnd={handleTransitionEnd}


* 의미: 애니메이션(트랜지션)이 완전히 끝나는 순간 handleTransitionEnd 함수를 실행합니다.
* 목적: 가짜 슬라이드에 도착했을 때, 유저 몰래 애니메이션을 끄고 진짜 슬라이드 위치로 순간 이동시키기 위해 사용합니다.

display: "flex",
transform: `translateX(-${currentIndex * 100}%)`,


* display: "flex": 자식 이미지들을 가로로 나란히 한 줄로 세웁니다.
* transform: currentIndex가 0이면 0%, 1이면 -100%, 2이면 -200% 만큼 왼쪽으로 통째로 밀어버립니다. 이 움직임 덕분에 화면에 다른 사진이 나타납니다.

transition: isTransitioning ? "transform 0.5s ease-in-out" : "none",


* 의미: isTransitioning이 true이면 0.5초 동안 부드럽게 스르륵 움직이고(ease-in-out), false이면 애니메이션 없이 칼같이 툭 순간 이동(none)합니다.
* 이유: 앞서 질문하신 '0.05초 타이머 코드'와 연계되어, 눈속임 위치로 순간 이동할 때는 none으로 만들어서 유저가 이동을 눈치채지 못하게 만듭니다.

## 3. 슬라이드 내부 이미지 반복 출력 (SLIDES.map(...))

{SLIDES.map((src, index) => (
    <div key={index} style={{ width: "100%", flexShrink: 0 }}>
        <img
            src={src}
            alt={`Slide ${index}`}
            style={{ width: "100%", height: "300px", objectFit: "cover", display: "block" }}
        />
    </div>
))}


* SLIDES.map: 원본 이미지 앞뒤로 복사본(가짜 슬라이드)이 추가된 전체 슬라이드 배열을 하나씩 꺼내어 화면에 그립니다.
* flexShrink: 0: 부모 박스가 좁아지더라도 이미지 박스 크기가 절대 줄어들지 않고 무조건 width: "100%"(600px)를 유지하도록 강제합니다.
* objectFit: "cover": 이미지 비율이 깨지지 않도록 가득 채우고, 넘치는 부분은 자연스럽게 잘라냅니다.

## 4. 하단 인디케이터 (현재 위치 점 표시기)

position: "absolute", bottom: "15px", left: "50%", transform: "translateX(-50%)",
display: "flex", gap: "8px"


* 슬라이더 하단 중앙에 점들을 가로로 이쁘게 배치하는 스타일입니다.

{IMAGES.map((_, index) => {
    let displayIndex = currentIndex;
    if (currentIndex === 0) displayIndex = IMAGES.length;
    if (currentIndex === SLIDES.length - 1) displayIndex = 1;


* IMAGES.map: 가짜 슬라이드가 아닌, 순수 원본 이미지 개수만큼만 점을 만듭니다. (예: 사진이 3장이면 점도 무조건 3개)
* displayIndex 조건문: 현재 currentIndex가 가짜 슬라이드(0번째나 마지막 번째)를 가리키고 있을 때, 하단 점은 엉뚱한 곳이 아닌 그에 매칭되는 실제 원본 인덱스 하이라이트를 켜도록 보정해 주는 수학적 계산 코드입니다.

background: displayIndex === index + 1 ? "#3b82f6" : "rgba(255,255,255,0.6)",
transform: displayIndex === index + 1 ? "scale(1.2)" : "scale(1)"


* 의미: 현재 화면에 보이는 이미지와 일치하는 점은 파란색(#3b82f6)으로 바꾸고 크기를 1.2배(scale(1.2)) 키워서 유저에게 "지금 이 사진을 보고 있어요"라고 시각적 힌트를 줍니다. 활성화되지 않은 점은 반투명한 흰색으로 보입니다.

## 구조 총정리
이 코드는 지금까지 질문하신 useRef 타이머, useEffect 0.05초 지연, 그리고 이 HTML 구조가 삼박자로 결합되어 작동합니다.

   1. useRef 타이머가 3초마다 currentIndex를 바꿉니다.
   2. transform이 작동해서 슬라이더가 0.5초간 부드럽게 스르륵 밀립니다.
   3. 맨 끝 가짜 슬라이드에 도달하면 onTransitionEnd가 발동되어 애니메이션을 none으로 끕니다.
   4. 그 순간 첫 번째 진짜 슬라이드 위치로 툭 이동시킵니다. (유저는 연속된 줄 압니다.)

import { useState } from 'react';

interface Todo {
  id: number;
  text: string;
}

export default function App() {
  const [todos, setTodos] = useState<Todo[]>([
    { id: 1, text: "React 공부하기" },
    { id: 2, text: "맛있는 저녁 먹기" },
  ]);

  const deleteTodo = (id: number) => {
    setTodos(todos.filter(todo => todo.id !== id));
  };

  return (
    <ul>
      {todos.map(todo => (
        <li key={todo.id}>
          {todo.text}
          <button onClick={() => deleteTodo(todo.id)}>삭제</button>
        </li>
      ))}
    </ul>
  );
}

          <li key={index}>
            {product.name} ({product.category})
          </li>
        ))}
      </ul>
